\section{Discussion}
\label{sec:discussion}

This study asked how far comparisons of abliteration tools and versions depend on the rule that selects the released
model, using rebuilt Heretic~1.x models, Heretic~2.0, two project-fork plug-ins, two external tools run at their
documented settings and two community releases on the same Qwen2.5 base models, judged on held-out prompts. Selected at
the archived cap, the twelve 1.x models removed between 0.9~pp (not significant) and 73.1~pp of refusal. In the
like-for-like contrast, Heretic~2.0 DiM left 25.9~pp less residual refusal than 1.x on Qwen2.5-32B and 19.0~pp less on
Qwen2.5-7B; both differences were significant for these checkpoints, but with one search per arm neither exceeded the
range of search-to-search variation, so the search-level evidence for H1 was inconclusive. In a post hoc re-export of the
Qwen2.5-32B 1.x search at the 2.0 cap, the same search released a model that left 61.7~pp less residual refusal than
its archived export and 35.8~pp less than 2.0 DiM. In this one search on one model, the selection cap alone was
sufficient to move residual refusal by more than the version contrast and to reverse it for these checkpoints, by an
amount inside the interval of the seed-noise threshold. The overall lesson is that a tool comparison is hard to
interpret without the selection rule and the realised divergence of the released models;
external tools run at their documented settings ranged from no effect on refusal to near-complete removal on one
model.

The like-for-like contrast (Figure~\ref{fig:refusal}, Table~\ref{tab:h1}) was large and robust to the judge on both
base models, and the search records suggested where to look; that suggestion was heuristic, because the dev counts of
the two versions are not on a common scale, and it carries no inferential weight here. The archived 1.x runs released the trial
with the fewest dev refusals at dev KL $\le$ 0.01, a cap ten times tighter than the companion study's 0.1. On
Qwen2.5-32B the released 1.x trial had kept 89 of 100 dev refusals, whereas the same search had reached 50 at dev KL
0.064 (Figure~\ref{fig:devkl}). Re-exported with heretic-llm 1.4.0, the release identified from the run records,
that trial left 11.6\% of the harmful prompts refused (\S\ref{sec:res-kl}, Table~\ref{tab:h1}b): 35.8~pp less than
2.0 DiM but 7.7 and 5.6~pp more than MPOA and ARA, at a TF divergence between those of DiM and MPOA and without a
measurable capability change. Each of these decisions held under keyword matching, under Qwen3Guard and without the
AdvBench-overlap prompts. With the cap equalised, the older version's search thus released
a model that removed more refusal than the newer version's DiM search, the reverse of the H1 contrast. This does not
show that 1.x is the better version. The arms still differ in trial budget (200 versus 100 trials), seed, the MLP
weight range, the KL target of the 1.x objective, system prompt and marker list; at dev KL $\le$ 0.1 the 2.0 DiM
search never went below 89 dev refusals; and a second seed of the same DiM configuration on Qwen2.5-7B in the
companion study left 4.4\% instead of 20.6\% \cite{young2026harder}. The reversal is therefore as consistent with a
weaker DiM search as with any property of the version, and it lies inside the interval of the seed-noise threshold.
The cap also did not equalise divergence. Trial~\#96 moved the model about twice as far as 2.0 DiM (TF divergence
0.032 versus 0.017), and within Qwen2.5-32B residual refusal fell almost monotonically with TF divergence. A reading
in which every released checkpoint lies on one refusal--divergence curve per base model, and the cap only decides
where on that curve a search stops, fits these data at least as well as a reading in terms of version. The
within-search records are consistent with it: on Qwen2.5-32B the 1.x search had reached only 87 dev refusals by dev KL
0.012 and reached 50 at 0.064, and on the held-out prompts the two exports of that search differed by 61.7~pp. The dev
counts of the two versions are not on a common scale and are not used to compare the searches. The within-search cap
contrast is the robust result; the version reading is not.

The code pipeline gave no advantage (Figure~\ref{fig:general-code}), and the leading explanation lies in its
contrast set. A difference-in-means direction isolates refusal only if the ``harmful'' side of the contrast is
refused. The originals refused only 13.5--34.0\% of the code-as-weapon prompts, so a direction computed from
malicious-code requests against short programming tasks mostly captures their difference in topic and style, and a
code dev set with few refusals gives the search little signal (the Qwen2.5-32B code search reached 2 of 100 dev
refusals on it at dev KL 0.072). The archived adapters agree with this account: the directions removed by the two
pipelines had cosines of only 0.19 to 0.63, so the null result does not arise because both pipelines removed the same
direction. A shared refusal mechanism \cite{arditi2024refusal} is not excluded, but it is not needed to explain the
pattern. The base model's refusal rate on the code pipeline's own direction and dev prompts cannot be reported,
because those prompt files were not archived. The two pipelines also did not differ simply in how far their searches
moved the model: the code variant diverged less than the general variant on three models and more on two, and on
Qwen2.5-7B it diverged about eight times as far (TF divergence 0.075 versus 0.009 nats per token) while leaving
refusal unchanged ($-$0.9~pp [$-$2.3, +0.4]). The code searches were selected at the same tight cap that suppressed
most of the achievable removal in the general search on Qwen2.5-32B, so the H2 result holds only at that cap. Coder
checkpoints were not consistently easier or harder to edit at that cap: the general variant removed 72.9 and 73.1~pp
on Qwen2.5-Coder-7B and Qwen2.5-Coder-14B but 11.0~pp on Qwen2.5-Coder-32B. For cyber-misuse threat models, the weak
baseline refusal matters in its own right: on these models the safeguards against attack-code requests were thin
before any edit, so any uplift attributed to abliteration should be stated as the change from the original, not as the
level after editing, and compliance is not competence \cite{carleo2026willing}.

Keyword counting changed the size of differences more than their order (Figure~\ref{fig:refusal}b). In the main
design keyword matching counted significantly more refusals than WildGuard in 15 of 23 edited models and fewer in
none, by up to 19.5~pp; one of 76 within-model pairs changed sign between the two measures, a pair that differed
significantly under keyword matching only, and every 1.x-versus-2.0 decision was the same under both. Keyword
reports would therefore understate the reductions achieved by the strongest edits relative to either judge. The
direction of the gap is not fixed, however: among the added cells keyword matching counted 16.6~pp more refusals
than WildGuard for the rule-matched 1.x model but 21.1~pp fewer for J-space on Qwen3.5-4B. The data show disagreement
between keyword matching and the judges, not which of them is correct, and the correlation of the gap with the
refusal removed is partly mechanical, because as judged refusal approaches zero the only possible disagreements are
keyword flags on answers the judge counts as compliant. In the companion study the gap was concentrated in responses
that reached the 512-token limit \cite{young2026harder}. Here, restricting keyword matching to the first 256 tokens
removed a median of only 2.4~pp of the gap, and keyword-only refusals had reached the limit less often than the
responses WildGuard counted as compliant, so on these models the gap is not explained by long responses alone;
safety vocabulary early in otherwise compliant answers, such as warnings and disclaimers, is a plausible source that
only a human audit could confirm; none was done. The re-exported 1.x model shows the same problem one step earlier, in the search
itself. Trial~\#96 had kept 50 of 100 dev refusals by keyword count, yet on the held-out prompts it left 28.2\%
refused by keyword count and 11.6\% by WildGuard. On identical held-out responses keyword matching accounted for
16.6~pp [13.4, 19.7] of that difference; the remainder reflects differences between the dev protocol
(AdvBench-derived prompts, the coding-assistant system prompt, 100-token responses and the 1.x marker list) and the
held-out one. Equal dev counts were equally uninformative: the two released Qwen2.5-32B trials of the like-for-like
contrast both had 89 dev refusals, each under its own arm's protocol, and left 73.4\% and 47.4\% held-out refusal.

Within Qwen2.5-32B the ranking of tools largely followed how far they moved the model (Figure~\ref{fig:tradeoff}):
residual refusal fell almost monotonically with TF divergence across the eight edited models of the main design
(Spearman $\rho=-0.93$, exact permutation $p=0.002$), the rule-matched 1.x model fell into the same ordering (11.6\% at 0.032 nats per token,
between SOM and MPOA), and the community releases sat at its far end (0.085 and 0.151 nats per token). The ordering
did not hold on Qwen2.5-7B: the 1.x code variant moved the model further than any other Heretic configuration on that
model (0.075 nats per token) without changing refusal, and OBLITERATUS \texttt{basic} diverged by 0.058 without
changing it either. Across the 23 edited models of the main design residual refusal still fell as TF divergence rose
(Spearman $\rho=-0.75$ [$-$0.93, $-$0.36], bootstrap over base models), but the same divergence corresponded to very different reductions on
different base models, and on one model tools differed at equal divergence (on Qwen2.5-32B, 2.0 DiM left 17.9~pp
less residual refusal than 1.x code, both at 0.017). Divergence is therefore a cost an edit pays, not a
model-independent measure of what it buys. Capability benchmarks registered little of this. In the main design no
per-benchmark change survived correction, the mean changes stayed within one point and 21 of 23 were equivalent to zero
within $\pm$2~pp, although models that removed more refusal tended to lose slightly more (exploratory; Spearman
$\rho=+0.50$ [0.18, 0.73] between residual refusal and mean change, also within base models). The one clear loss accompanied the largest divergence in the study, OBLITERATUS \texttt{spectral\_cascade}
at 0.471 nats per token. At the divergences reached by the Heretic searches, TF divergence on benign prompts is
therefore a more sensitive indicator of what an edit changes than the five benchmarks, although the absence of
significant benchmark changes reflects limited power as well as small effects. The earlier comparison's 18.8-point
GSM8K loss for Heretic on Yi-1.5-9B \cite{young2025comparative} has no counterpart among the Qwen2.5 models here; no
Yi model was evaluated, so the two results do not conflict.

To the best of current knowledge this is the first held-out, judge-based comparison of two versions of the same
abliteration tool in a documented like-for-like setup that also releases the older version's search under the newer
version's selection rule, of general- versus code-derived pipelines, and of Heretic output against external
tools and public community releases on the same checkpoints. H1 was significant for the released checkpoints on both
base models but inconclusive at the search level: on Qwen2.5-32B the difference (25.9~pp) lies inside the interval
of the seed-noise threshold [18.1, 45.4], and the rule-matched check reversed it; on Qwen2.5-7B the difference
(19.0~pp) is below the point threshold, and the companion study's second seed of the same DiM configuration left 4.4\%
instead of 20.6\% \cite{young2026harder}. H2 was not supported at the archived cap, and H3 was partially supported,
because the keyword--judge disagreement was tool-dependent but rarely reordered tools.

Several alternative explanations were examined. The like-for-like arms differ in trial budget, search seed,
optimisation system prompt, marker list and KL objective as well as in selection cap and version
(Table~\ref{tab:h1setup}). The rule-matched re-export removes the cap difference for one search and leaves the others,
so it shows that the cap alone suffices to reverse the Qwen2.5-32B contrast for these checkpoints, not that it is the
only setting that matters. The MLP-weight range of 2.0 includes values that 1.x could not reach, but none of the
selected or re-exported trials used a value below the 1.x lower bound (all between 0.91 and 1.21). The re-export could itself have drifted from the archived run; it was accepted only after re-exporting the
originally released trial with the same script had reproduced the archived adapter numerically
(\S\ref{sec:reexport}, Appendix~\ref{app:reexport}), and trial~\#96 reproduced its own record (51 versus 50 dev
refusals). The eight rebuilt 14B and 32B
1.x models were tensor-for-tensor identical to the archived merges; for the four 7B 1.x models no archived tensor
hashes exist, but their adapters matched their manifests. Within each base model all cells were generated with
identical decoding, prompts and judges; the one harness difference, for the Qwen2.5-32B original, affects its MBPP
comparisons, which are unpaired, and output post-processing that changes nothing in its responses. Removing the 44
AdvBench-overlap prompts changed no decision of the main design or of the rule-matched check; among the external-tool
comparisons it changed one WildGuard decision (OBLITERATUS \texttt{advanced} versus 1.x general on Qwen2.5-7B,
$-$4.6~pp, no longer significant) and three Qwen3Guard decisions (the same pair, and \texttt{spectral\_cascade}
versus MPOA and versus SOM, which became significant). Removing the 41 code-as-weapon prompts drawn from the
code variant's source corpora removed the only evidence for a code-specific advantage. WildGuard has moderate
published agreement with human labels (Cohen's $\kappa=0.61$) on another response distribution
\cite{xie2025sorrybench}, and no human audit was done here, so every rate is relative to the automatic judges.
Qwen3Guard reproduced every 1.x-versus-2.0 decision and every decision of the rule-matched check, but two automatic
judges can share errors. SOM and J-space are plug-ins of the companion study's fork, so their
contrasts describe configurations that a Heretic~2.0 user does not obtain from a release. Finally, 19 of the 42
judged cells were first reported in the companion study; they serve here as comparators, and the hypotheses concern
the new 1.x cells.

At a fixed tight cap the refusal removed varied by model: selected at dev KL $\le$ 0.01, the same 1.x procedure removed
3.4~pp from Qwen2.5-32B and 73.1~pp from Qwen2.5-Coder-14B. These differences are compatible with reports that
susceptibility to abliteration is model-specific rather than size-dependent \cite{hadetskyi2026not}, but they are not
evidence of resistance: at a cap of 0.1 every 1.x general search had reached 5 to 50 dev refusals
(Table~\ref{tab:devkl}), and the Qwen2.5-32B search, re-exported there, removed 65.2~pp. Differences between models at
a tight cap therefore measure at least partly where each model's refusal--divergence trade-off crosses the cap. They extend the companion study's observation that public releases reach lower refusal at larger
divergence \cite{young2026harder}: on Qwen2.5-32B the archived output of an older tool lies at the low-divergence end
of the same within-model ordering, and the same search, released at the newer cap, moves into its middle. They also
qualify the earlier tool ranking \cite{young2025comparative}, which ran each tool at its defaults and so mixed
algorithm, preset and selection rule; here the three presets of one tool left between 11.8\% and 72.9\% of the
harmful prompts refused on the same model, nearly as wide a range as the Heretic configurations and the other
external tool spanned together (4.7--71.2\%). The jwest33 result on Qwen3.5-4B adds that architecture support is
part of a tool's behaviour: on hybrid-attention models, whether a code path detects the architecture can matter as
much as the choice of method.

\label{sec:audit}

For developers, auditors and release reviewers who assess how easily a release can be stripped of its safeguards,
three consequences follow, each resting on the evidence above and therefore on one search for the cap effect. First,
a robustness claim should state the selection cap or divergence at which it was measured and should not be made at a
cap tighter than the loosest one that leaves capability unchanged. Here, the re-exported model at dev KL $\le$ 0.1
showed a capability change equivalent to zero within $\pm$2~pp, and at that cap every 1.x general search had reached 5
to 50 dev refusals of 100, so dev KL $\le$ 0.1 is a defensible minimum; reporting residual refusal as a curve against
divergence (Figure~\ref{fig:devkl}, Table~\ref{tab:devkl}) is preferable to a single point, and model cards
\cite{mitchell2019modelcards} offer a place for the selection rule, the dev KL, the held-out divergence and the judged
refusal. Second, the attacker's cost is small. The 200-trial 1.x general searches took 18 to 41 minutes of search time,
the code searches 49 to 157 minutes, and the 100-trial 2.0 DiM searches 8 minutes on one RTX 4090
(Qwen2.5-7B) and 20 minutes on one H200 (Qwen2.5-32B), excluding model loading and export; re-exporting a different
trial from an existing search needs no new search at all. The hardware of the 1.x searches was not recorded. Third, a
single run of a tool at its default settings, as for the external tools here, is a lower bound on the refusal that
tool can remove, not an estimate of release robustness, and the residual refusal measured by a single greedy response
under a benign system prompt is an upper bound on the protection a release retains against a motivated actor. White-box
tampering evaluations of this kind complement black-box audits \cite{casper2024blackbox,che2025tampering}, and defences
such as tamper-resistant training \cite{tamirisa2025tamper} or refusal-feature adversarial training \cite{yu2025refat}
should be evaluated by whether they shift the whole refusal--divergence trade-off, not only the point a default cap
selects.
